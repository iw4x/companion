# companion - Steam friends presence for IW4x.

`companion` is a Steam client module that sets the title that Steam friends
see for IW4x.

## Usage

On Windows the game comes with `companion` and loads it into the Steam
client. On Linux the Steam client is started with the `companion` launcher
from the `linux/` subdirectory of the IW4x installation. To build and install
`companion` from source, see [libcompanion/README.md](libcompanion/README.md).

## Development

The development setup uses the standard `bdep`-based workflow and needs a
C++26 compiler. On Linux, with GCC 16 or later:

```
git clone https://github.com/iw4x/companion.git
cd companion

bdep init -C @gcc cc config.cxx=g++ --create-host-config
bdep update
bdep test
```

The man page and the manual (`libcompanion/doc/manual.cli`) are generated by
[CLI](https://codesynthesis.com/projects/cli/). In this setup `bdep` builds
`cli` in the host configuration that `--create-host-config` creates.
Consumers of the package build from the generated copies that its
distribution carries and don't need `cli`.

The Linux module is built for i386. Add an i386 configuration, which needs
the 32-bit glibc and libstdc++ development files (`glibc-devel.i686` and
`libstdc++-devel.i686` on Fedora, for example):

```
bdep init -C @gcc32 cc config.cxx="g++ -m32" \
  config.cxx.target=i686-linux-gnu           \
  config.c="gcc -m32"                        \
  config.c.target=i686-linux-gnu
bdep update @gcc32
bdep test @gcc32
```

GCC only reports the i386 target that `-m32` selects if it is built with
multiarch support (Debian, Ubuntu), which is why the configuration specifies
the target explicitly.

The Steam client only loads the Linux module at startup. The `steam-restart`
script installs the module from the `@gcc32` and `@gcc` configurations,
restarts the Steam client with it, and prints its diagnostics:

```
libcompanion/etc/private/steam-restart \
  --install ../companion-gcc32         \
  --install ../companion-gcc
```

`companion` is also built and tested for Windows. From Linux, add a MinGW-w64
GCC configuration that runs the tests under Wine. Wine has to find the MinGW
runtime DLLs, so the test runner adds their directory to `WINEPATH` (here, as
on Fedora):

```
bdep init -C @mingw cc config.cxx=x86_64-w64-mingw32-g++ \
  config.test.runner="env WINEPATH=/usr/x86_64-w64-mingw32/sys-root/mingw/bin wine"
bdep update @mingw
bdep test @mingw
```

On Windows, with MinGW-w64 GCC from [MSYS2](https://www.msys2.org/) in
`PATH`:

```
git clone https://github.com/iw4x/companion.git
cd companion

bdep init -C @mingw cc config.cxx=g++ --create-host-config
bdep update
bdep test
```

In PowerShell, a leading `@` has a special meaning (splatting), so write the
configuration name as `-@mingw`, which `bdep` also accepts:

```
bdep init -C -@mingw cc config.cxx=g++ --create-host-config
```
